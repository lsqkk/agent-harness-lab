# Agent Harness Lab

一个中文交互实验室，从一次工具调用讲起。你可以逐步检查模型收到的消息、工具返回的结果和工作区的每次变化，再亲手触发写入冲突。

## 打开实验室

克隆仓库后，在仓库根目录运行。需要 Node.js 22+，无需安装依赖。

```sh
npm start
```

打开 [本地实验室](http://127.0.0.1:4173/)。四个实验在浏览器里使用脚本化模型响应和内存文件。网页运行期间无需联网，也无需 API Key。静态站点的入口是 [`docs/index.html`](docs/index.html)。在 GitHub Pages 里可以选择 **Deploy from a branch → `main` → `/docs`**，也可以将整个 `docs/` 交给静态托管服务。

| 实验 | 看什么 |
| --- | --- |
| 第一次工具调用 | 模型要读 `config/app.json`，工具结果带着同一个调用 ID 回到下一轮。 |
| 读错路径以后 | 工具返回 `FILE_NOT_FOUND`，模型改用列目录，找到文件并提交修改。可以分别试一次批准和拒绝。 |
| 审批期间文件变了 | 点击「模拟手动编辑」再批准旧预览，得到 `CONFLICT`。下一份预览以新内容为基础，最终同时保留你的语言设置和模型的主题修改。 |
| 工具边界与预算 | 项目范围外的路径被拒绝。模型继续调用工具时，Harness 在执行前截住超出预算的请求。 |

点击时间线里的模型事件，再展开「请求上下文」，就能检查本轮的 `messages` 和 `tools`。切到「工作区」可以查看选中事件发生后的文件。自动运行遇到审批会暂停，处理后可继续逐步执行或再次自动运行。导出的 JSON 保存已经发生的事件，导入后可从头播放，不会重跑工具。要改选审批结果，重置实验后重新执行。

## 从一次工具调用理解 Harness

**模型负责决定要问什么、想调用哪个工具、如何解释结果。Harness 是运行这轮交互的程序，负责提供上下文和工具、调度执行、接收结果、管理状态与退出条件。** 工具是实际执行动作的函数，例如读取一个文件。用户界面则把请求、进度和需要人决定的部分呈现出来。

以「这个项目用什么主题」为例：

1. Harness 把任务和 `read_file` 的工具定义交给模型。定义描述函数和参数。代码里的工具实现仍在宿主程序内。
2. 模型返回一条 `assistant` 消息，其中包含如下调用。API 的 `arguments` 字段是 JSON 字符串，Harness 要解析并校验它。

   ```json
   {
     "id": "read-1",
     "type": "function",
     "function": {
       "name": "read_file",
       "arguments": "{\"path\":\"config/app.json\"}"
     }
   }
   ```

3. Harness 校验路径后运行 `read_file`，把结果编码成一条 `role: "tool"` 消息。`tool_call_id: "read-1"` 将结果和请求配对。若助手在同一轮提出多个调用，本项目按顺序处理，并在下一次请求前给每个调用附上结果。
4. 下一次请求带上原任务、助手的调用消息和工具结果。模型才有足够信息回答「主题是 light」。如果它继续调用工具，Harness 再执行一轮。一次模型请求加零个或多个工具结果，是这里的循环单位。 [DeepSeek 工具调用文档](https://api-docs.deepseek.com/guides/tool_calls/)

### 一次写入为什么要拆成预览和应用

工具只接受已登记的参数和样例项目内的路径。`replace_text` 要求原文本恰好出现一次，再根据当前内容生成替换预览。预览带着文件修订号。批准时，Harness 检查修订号是否还相同。如果你在中间改了文件，工具回传 `CONFLICT`，旧预览无法覆盖你的编辑。模型可以重新读取、重新提案，再等一次审批。拒绝同样作为 `DENIED` 回到模型，它可以据此准确说明写入没有发生。

校验解决「这次调用能执行吗」，审批解决「用户是否允许这次具体修改」，修订号解决「用户看到的那份预览现在还适用吗」。轮次和工具预算则给循环一个由程序执行的退出条件，即使模型一直请求同一个工具也会停下来。

### 从网页脚本到现在

这个仓库最初是 **DeepSeek Skills**。油猴脚本在聊天页面里寻找 `[[COMMAND={…}]]`，把命令交给本地 Node.js 桥接器。读取结果通过剪贴板由用户贴回聊天框。旧项目已经形成「模型提出动作 → 本地工具执行 → 结果回到模型」的轮廓。后来的本地 CLI 草稿补上了自动反馈，但仍依赖网页结构和文本解析。

新版把这条循环写成可检查的程序，保留旧演示图和 Git 历史。可用 `git show 63420a1:README.md` 阅读旧说明。反向代理解决请求如何到达另一个服务。Harness 关心本轮发什么、工具如何执行、结果何时回到模型，以及何时暂停。

## 从终端运行

```sh
npm run lab -- read
npm run lab -- recover --output run.json
npm run lab -- conflict
npm test
```

`--output` 写入一份可在网页导入的轨迹，已有文件会保留。交互式终端可以批准或拒绝修改，也能用 `e` 模拟手动编辑。非交互终端会拒绝写入。`budget` 实验按设计会触发停止状态，命令返回退出码 1。

如果想观察真实模型的选择，先在当前终端设置 `DEEPSEEK_API_KEY`，然后运行：

```sh
npm run lab -- recover --live --output deepseek-run.json
```

这会用官方 API 发送实验提示、工具定义及必要的样例内容，并可能产生 API 费用。可以用 `--model` 选择 API 支持的模型。CLI 会打印用量，审批和工作区仍由同一个 Harness 管理。真实模型可以选择和脚本不同的路径。轨迹保存消息和样例内容，请在分享之前先查看文件。 [DeepSeek API 文档](https://api-docs.deepseek.com/guides/tool_calls/)

## 代码入口

| 文件 | 职责 |
| --- | --- |
| [`docs/harness.mjs`](docs/harness.mjs) | 消息循环、工具执行、审批和运行记录 |
| [`docs/scenarios.mjs`](docs/scenarios.mjs) | 四组样例任务和根据工具结果分支的脚本化模型 |
| [`docs/app.mjs`](docs/app.mjs) | 网页交互、轨迹检查和回放 |
| [`docs/trace.mjs`](docs/trace.mjs) | 浏览器和 CLI 共用的轨迹格式 |
| [`deepseek.mjs`](deepseek.mjs) | DeepSeek 官方 API 适配器 |

实验的工作区只在内存里，重置或退出就会丢弃变化。真实编辑器还需要处理文件系统权限、并发写入、会话恢复和持久化。这个实验室把这些问题缩成一个可以逐步看完的循环。
